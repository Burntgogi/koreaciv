### 1.2 단계별 절차 (`pipeline/build_ridges.py`)

```text
[SRTM30+ CSV] ──(EPSG:5179 800m 재투영)──▶ [DEM 래스터 850×760]
                                                 │
[WAMIS 396 하천 + 호수] ──(Stream Burning)───────┤
                                                 ▼
                                    [Priority-Flood 함몰 채움]
                                                 │
                                    [D8 흐름 방향 · 누적(FA)]
                                                 │
                                    [유역 분할 (하천 본류·지류·해안 출구)]
                                                 │
                          [유역 경계 쌍대선(Divide Graph) 추출]
                                                 │
                          [산자분수령 검사: 하천 교차 0건 강제]
                                                 │
                     [위계 산정(유역면적·기복·표고) + 가지치기]
                                                 │
                      [위상 보존 단순화 + 정점별 굵기 계산]
                                                 ▼
                                    [data/ridges.json (≤ 180 KB)]
```

1. **EPSG:5179 정규 래스터화 (`800 m` 해상도)**:
   - SRTM30+ 원시 간격(약 0.75–0.93 km)과 1:1에 가까운 **800 m 격자**(`world.json` 영역 `0..6647 × 0..6350` 기준 약 `930 × 890` 셀, `1 cell = 7.143 world units`)로 `pyproj` + `scipy.interpolate.RegularGridInterpolator`(bilinear) 리샘플링한다.
   - `world.json`의 `owner >= 0`과 `foreign == 1` 육각 칸 영역을 800 m 래스터로 래스터화해 `rok_mask`, `foreign_mask`, `sea_mask`를 만든다.
2. **하천 각인(Stream Burning) + 함몰 채움(Pit Filling)**:
   - `rivers` 396개 선분과 `lakes` 폴리곤을 800 m 래스터에 래스터화(`rasterio.features.rasterize`)한다.
   - 각인 깊이: 5대 본류(`main=true`) `-150 m`, 국가하천(`tier=1`) `-80 m`, 지방하천(`tier=2`) `-35 m`, 호수 `-50 m`. 각인 픽셀의 8방 인접 1셀에 `-12 m` 완경사 둑(trench)을 더해 계곡 바닥이 인접 능선보다 반드시 낮게 만든다.
   - Barnes(2014) **Priority-Flood** 알고리즘(min-heap, Python/NumPy 또는 `heapq`로 80만 셀 기준 1–2초)으로 해안 경계에서 안쪽으로 함몰지(sink)를 채우되, 평탄부에 `1e-4 m` 미세 경사를 부여해 모든 육지 픽셀이 단조 하강 경로로 바다 또는 도곽 경계에 도달하게 한다.
3. **D8 흐름 방향 · 흐름 누적(`FA`) · 유역 분할**:
   - 8방 최대 경사(`(z_i - z_j) / dist`)로 `flow_dir`를 구하고 위상 정렬 순으로 흐름 누적 면적 `FA[p]`(km² 단위: 셀 수 × `0.64 km²`)를 합산한다.
   - **유역(Basin) 라벨링**: 바다 출구(해안 도달점)마다 고유 유역 ID를 부여하고, 추가로 5대 본류 및 국가하천 합류점(`FA >= 400 km²`인 분기점)에서 좌·우 지류를 하위 유역 ID로 세분화한다. 이렇게 하면 한강–낙동강 대분수계뿐 아니라 남한강–북한강, 금호강–낙동강 본류 사이의 주요 지맥 분수계까지 자동으로 잡힌다.
4. **분수계 그래프 추출 + "산은 물을 건너지 않는다" 검사 규칙**:
   - 인접한 두 육지 셀 `(p, q)`의 유역 ID가 다르고, 두 셀 모두 하천 각인 픽셀이 아닐 때, 두 셀 사이의 **격자 쌍대 변(dual edge)**을 분수계 후보 간선으로 채택한다. (서로 다른 유역이 맞닿는 변의 집합은 수학적으로 닫힌 분수계망을 이룬다.)
   - **검사 가능한 불변 규칙(Hard Invariant — 산자분수령)**:
     - 모든 `rivers` 396개 선분에서 발원지 끝단 `1.5 km`(하천 시점 2셀)를 제외한 구간 `R_body`와 `lakes` 내부 폴리곤으로 `shapely.STRtree`를 구성한다.
     - 1단계(추출 시): 분수계 간선이 `R_body` 또는 `lakes`와 교차(`intersects`)하거나, `FA[p] > 25 km²`인 하곡 바닥 셀을 가로지르면 해당 간선을 **즉시 절단·제거**한다.
     - 2단계(단순화·스플라인 검증 시): 단순화(Douglas-Peucker) 결과 선분이 `R_body`와 교차하면 교차 선분의 허용 오차를 절반으로 줄여 재분할(recursive bisection)해 교차를 회피한다.
     - **빌드 통과 조건(Assert)**: `count(ridge_segments intersecting R_body) == 0`. 1건이라도 남으면 빌드 실패로 중단한다.
5. **위계(굵기) 산정과 가지치기**:
   - 단순 표고만 쓰면 고원 평지가 굵어지고, 유역 차수만 쓰면 평야 분수계가 굵어진다. 두 축을 결합한다.
   - 각 분수계 변 `e`가 가르는 양쪽 유역의 누적 면적 중 작은 쪽 `A_sep(e) = min(Area_left, Area_right)`(km²)와, 다중 스케일 가우시안 평활 표고 `Z_2km(e)`(σ=2 km)·`Z_6km(e)`(σ=6 km) 및 국지 기복 `Rel_3km(e)`(반경 3 km 내 표고 표준편차)를 계산한다.
   - **위계 점수**:
     $$S(e) = 0.55 \cdot \mathrm{clamp}\!\left(\frac{\log_{10}(\max(A_{\text{sep}}, 10)) - 1}{3.2},\, 0,\, 1\right) + 0.30 \cdot \mathrm{clamp}\!\left(\frac{Z_{2\text{km}}}{1200},\, 0,\, 1\right) + 0.15 \cdot \mathrm{clamp}\!\left(\frac{\mathrm{Rel}_{3\text{km}}}{180},\, 0,\, 1\right)$$
   - **4단계 위계(`tier`) 및 가지치기**:
     - `tier 3` (대분수계·주능선): `S >= 0.62` 또는 동·서해/남해 대유역(5대강 본류 간) 경계이면서 `Z_2km >= 180 m`
     - `tier 2` (광역 지맥): `0.44 <= S < 0.62` 및 체인 길이 `>= 18 km`
     - `tier 1` (지역 능선): `0.28 <= S < 0.44` 및 체인 길이 `>= 10 km`, `Z_2km >= 140 m`
     - `tier 0` (국지 구릉능선): `0.18 <= S < 0.28` 및 체인 길이 `>= 6 km`, `Rel_3km >= 45 m`
     - 그 미만 막다른 잔가지(spur)는 말단에서 반복 가지치기(iterative leaf pruning)로 제거한다.
   - **정점별 가변 폭(`w`, 0..15 정수)**: 선분 `tier`의 기본 폭에 정점 표고·기복을 곱해 봉우리 부근은 두껍고 고개(안부)에서는 잘록하게 좁아진다:
     `w_norm(v) = baseTierWidth[tier] * (0.65 + 0.55 * clamp(Z_2km(v) / 1100, 0, 1))`.
6. **위상 보존 단순화 및 클라이언트 곡선화·먹필 리본**:
   - 분기점(`degree != 2`)과 주요 봉우리 정점을 고정(pin)한 채 체인 단위로 Douglas-Peucker 단순화(`ε = 2.0 world units ≈ 224 m`)를 수행한다.
   - 렌더링(`terrain.js`): 체인 정점을 centripetal Catmull-Rom(`α = 0.5`, 세그먼트당 3–4 분할)으로 보간한 뒤, 정점 법선 양쪽으로 `±halfWidth(v)`를 벌린 **단일 닫힌 리본 폴리곤**으로 채운다.
   - 기존 직선 톱니(`teeth`)는 폐기하고, 북서 사광(`[-0.6, -0.8]`)의 반대쪽인 남동 사면에만 리본 폭의 `1.1–1.6배` 오프셋으로 **연먹 사면 바림(`alpha 0.14`, 렌즈 시 끄기)**을 1패스 얹는다.

### 1.4 사전 계산 JSON 형식과 크기 예산

- 파일: `data/ridges.json` (신여지도 전용 정적 파일 — `site/` 초기 번들에 영향 없음, `world.json`과 병렬 fetch).
- 스키마(정수 양자화 — 좌표 10배 스케일 정수, 폭 `0..15` 정수):
  ```json
  {
    "version": "phase5c-20261001",
    "method": "SRTM30+ (30 arc-sec) + WAMIS 396 rivers stream-burned D8 watershed divides",
    "scale": 10,
    "river_crossings": 0,
    "chains": [
      { "t": 3, "f": 0, "bb": [2810, 1120, 3420, 2980], "p": [2814,1125,2831,1160,...], "w": [9,11,13,...] }
    ],
    "peaks": [
      { "x": 4120, "y": 2180, "e": 1708, "t": 3 }
    ]
  }
  ```
  (`t`: tier 0–3, `f`: `0`=대한민국·`1`=외국, `bb`: 타일 컬링용 월드 bbox, `p`: `[x0,y0,...] × 10` 정수, `w`: 정점 굵기 `0..15`).

## 2. 먹→빛깔 연속 전환 설계 (2-A 구체화)

1회차 2-B(WebGL2)는 컨텍스트 소실·폴백 이중화로 인해 보류/폐기하고, **2-A(이중 판목 타일 캐시 알파 블렌딩)**를 60fps 프레임 예산 안에서 돌아가게 설계한다.

### 2.1 핵심 병목 해소: 연속 축척 캐시 → 이산 Mip 피라미드

현재 `terrain.js`는 `this.s = cam.scale * dpr`을 연속값으로 써서 휠을 돌릴 때마다 캐시 전체가 무효화된다. 이를 **$\sqrt{2}$ 배율 Mip 피라미드**(`level = round(2 * log2(cam.scale / fitScale))`, 즉 `z = 1.0, 1.41, 2.0, 2.83, 4.0, 5.66, 8.0, 11.3`)로 바꾼다.
- 줌 중에는 현재 가장 가까운 Mip 타일을 `drawImage`로 보간 확대·축소하므로, **줌이 멈출 때까지 기다리지 않고도 매 프레임 먹판과 채색판이 동시에 존재**한다.
- 정지 후(`160 ms`) 현재 `cam.scale`이 Mip 경계를 넘었을 때만 새 Mip 타일을 점진 교체한다.

### 2.2 판목 분리와 합성 구조

| 판목 | 생성 조건 (`rc` = CSS 칸 반지름) | 포함 레이어 | 비고 |
|---|---|---|---|
| **먹판 (`inkTiles`)** | `rc < 14.0` (전도~전이 구간) | 한지 바탕, 연안 3겹 쪽빛 바림, 파문, 4단 수묵 음영(`cInk`), 호수(먹), 강(단선), 산줄기(농먹 `0.88`), 해안·시도 경계·휴전선 | `k = 0` 고정 |
| **채색판 (`pigTiles`)** | `rc > 4.5` (전이~근접 구간) | 석채 피복 바탕(`cPig`), 갯벌 점묘, 호수(채색), 칸 금(`0.14`), 길·철도, 피복 무늬, 큰 강 2줄, 산줄기(연먹 `0.36`), 해안·시군구·시도·휴전선 | `k = 1` 고정 |
| **렌즈판 (`lensTiles`)** | 렌즈 활성 시 (`pigTiles` 대체) | 연한 수묵 음영(50% 감쇠) + `multiply` 안료 + 자료없음 빗금 + 칸 금 + 강 + 산줄기(`0.42`) + 경계 | 렌즈 켜면 `pigTiles` 즉시 해제 |

- **선 선명도 유지**: 해안선·시도 경계·휴전선·강·산줄기를 먹판과 채색판의 **동일 월드 좌표**에 각각 적절한 농도로 그려 둔다. 알파 블렌딩 중 `A·(1-k) + B·k`에서 동일 좌표의 선은 흐려지지 않고, 산줄기는 자동으로 `0.88 → 0.36`으로 부드럽게 물러나며 칸 금·피복 무늬는 `0 → 1`로 배어 나온다.

### 2.3 확대 중 보간식과 프레임 예산

- **보간식**:
  ```js
  const rc = grid.R * cam.scale; // CSS px 단위 육각 반지름
  const t = Math.min(1, Math.max(0, (rc - 5.5) / (12.0 - 5.5)));
  const k = t * t * (3 - 2 * t); // smoothstep(5.5, 12.0, rc)
  ```
  - `k === 0`: `inkTiles`만 `blit` (`alpha = 1`).
  - `0 < k < 1`: `inkTiles`를 `alpha = 1`로 `blit`한 뒤, 그 위에 `pigTiles`를 `globalAlpha = k`로 `blit`.
  - `k === 1`: `pigTiles`만 `blit` (`alpha = 1`).
- **타일 크기와 프레임 예산**:
  - 타일 크기: **`512 × 512` 기기 픽셀** (`1장 = 1.0 MB` RGBA GPU/RAM).
  - 매 프레임 `drawImage` 합성 비용: 데스크톱 1920×1080(`DPR=1`: 12–15장, `DPR=2`: 30–40장) 기준 **0.8–2.2 ms**.
  - 타일 신규 굽기 시간 예산: **줌·패닝 중 `5 ms/frame` (최대 1장)**, 정지 후 **`12 ms/frame` (최대 2장)**. 뷰포트 중심과 거리가 가까운 타일부터 우선(center-out) 굽는다.

### 2.4 메모리 예산(LRU 상한) · 저사양 · Reduced-Motion

| 환경 | DPR 상한 | `inkTiles` LRU | `pigTiles`/`lensTiles` LRU | 총 타일 메모리 상한 |
|---|---|---|---|---|
| **데스크톱 기본** | `min(dpr, 2)` | 36장 (36 MB) | 36장 (36 MB) | **≤ 72 MB** (전이 구간 외 36 MB) |
| **모바일 / 4 GB 이하 기기** | `min(dpr, 1.5)` | 14장 (14 MB) | 14장 (14 MB) | **≤ 28 MB** |
| **저사양 폴백** (`deviceMemory ≤ 2` 또는 10프레임 연속 `> 28 ms`) | `1.0` | 단일 판 14장 | — | **≤ 14 MB** (`rc = 8.5` 경계에서 1회 220ms 교차 전환) |

- LRU에서 퇴출되는 타일은 반드시 `cv.width = 0; cv.height = 0;`으로 명시 해제해 iOS Safari 캔버스 메모리 한도(약 256–384 MB) 초과 리로드를 차단한다.
- **`prefers-reduced-motion: reduce`**:
  - 카메라 `flyTo`·관성 스크롤·렌즈 `620 ms` 교차 페이드를 모두 `0 ms` 즉시 전환으로 끈다.
  - 단, `k = smoothstep(5.5, 12.0, rc)` 자체는 사용자가 직접 휠/버튼으로 배율을 바꿀 때의 공간 상태 매핑이므로 그대로 유지한다(원치 않는 자동 움직임이 아님).

### 3.1 `multiply` 합성 규칙과 종이 대비 보정

- **문제**: 기존 `source-over (alpha 0.93)` + 저명도 적갈색(`#8E2A1B`)은 한지 결과 산줄기를 덮어 "붉은 벽"을 만든다. 반면 `multiply`를 무보정으로 쓰면 한지 바탕(`#FBF6E8`, RGB 251·246·232)과 기복 음영이 곱해져 전체가 탁하고 어두워진다.
- **해법 (3가지 규칙)**:
  1. **바탕 음영 50% 감쇠**: 렌즈 활성 시 육지 바탕을 `LAND_INK (#FBF6E8)` + 기복 음영 진폭 `±0.08`(기존 `±0.16`의 절반)으로 깔아 종이결과 지형 입체감만 은은히 남긴다.
  2. **감산 합성 강도**: 육각 칸 채움 시 `ctx.globalCompositeOperation = 'multiply'`, **`globalAlpha = 0.82`**로 찍은 뒤 즉시 `'source-over'`로 복구한다.
  3. **최소 명도 하한선**: 한지 위 `multiply@0.82` 적용 후 결과색의 Oklab 명도 **`L ≥ 0.50`**, 먹선(`#1D1A16`) 대비 **`≥ 2.9:1`**(현판·시도 글자는 `#FBF6E8` 후광 포함 `≥ 7.0:1`)을 강제한다. 33종 전 팔레트를 Oklab/Oklch 보간으로 계산해 흑백(명도만)으로 봐도 순차 계단이 단조 감소하도록 설계한다.

1. **우선순위 점수 `P(c)`** (높은 순으로 먼저 배치):
   - 선택된 도시: `+10,000`

     - 2차(1차 모두 충돌 시, 1등급 도시에만 허용, 거리 `20px` 꺾임 지시선): `W-far(12) → E-far(12) → S-far(14) → N-far(14)`

     - 이미 배치된 현판 박스(여백 `4px`) 또는 다른 1등급 도시 자리 점(`반지름 6px`)과 겹치면 해당 후보는 즉시 실격.

3. **시도 이름과의 관계**: 기존판(`site/js/main.js:183`)과 동일하게 ① 1등급 현판 배치 → ② 시도 이름(`강원·경기·충남…`)을 현판 회피 위치에 배치 → ③ 시도 이름과 겹치는 하위 일반 시·군 묵서만 숨긴다.

## 8. 수상작 심사위원의 가장 아픈 비판 5개와 대응

### 비판 1. "고지도 껍질을 씌웠을 뿐, 기능 8종 보고서·33종 렌즈·18종 세부 층·미니맵을 다 얹으면 결국 무거운 GIS 대시보드로 회귀한다."
- **공격 지점**: 기존판과 기능 동등성을 맞추려다 신여지도의 최대 무기인 '한 장의 종이 여백미'가 붕괴할 위험.
- **대응**: **"기본 상태 침묵(Quiet Default)"**을 절대 규율로 잠근다. 첫 진입 전도에서는 8종 보고서·렌즈 목록·18종 세부 층·미니맵·고을 장이 모두 닫혀 있고, 캔버스 도판이 화면 면적의 **78% 이상**을 차지한다. 모든 고급 기능은 난외 주기(장부·갈피·층)를 눌렀을 때만 한지 접지처럼 펼쳐지고 `Esc` 한 번으로 다시 종이 한 장으로 돌아온다.

### 비판 2. "'먹에서 빛깔로'는 줌 한 번 해 보면 끝나는 1회성 기믹이다. 통계 렌즈를 켜는 순간 핵심 개념이 사라지고 평범한 단계구분도가 된다."
- **공격 지점**: 지형 모드와 렌즈 모드의 시각적 단절.
- **대응**: 렌즈 모드를 "색 덮어쓰기"가 아니라 **"목판 덧찍기(`multiply`)"**로 통합해, 렌즈를 켜도 한지 결·수묵 기복 음영·분수계 산줄기·물줄기가 안료 아래로 살아 숨 쉬게 만든다. 또한 확대하면 렌즈 위에서도 칸 금·시군구 점선·범주 목판 무늬(`rc ≥ 6`)가 배어 나와 "다가갈수록 정교해지는 판"이라는 개념이 지형과 통계 양쪽에서 일관되게 유지된다.

### 비판 3. "산줄기가 《산경표》도 아니고 공식 산맥도 아닌 자체 계산선이라면, 230개 공공 출처를 내세운 통계 지도로서 지리적 신뢰성에 흠이 생긴다."
- **공격 지점**: Webby / 데이터 저널리즘 심사위원이 가장 집요하게 검증하는 '사실과 연출의 경계'.
- **대응**: 자체 계산선임을 숨기지 않고 오히려 **재현 가능한 수치 지형학(SRTM30+ + WAMIS 396 하천 교차 0건 검증)**으로 정면 공개한다. 고유 산맥명을 붙이지 않고 지도표와 연감에 계산 방식과 한계(해안·평야·북한 자료 경계)를 명시한다. "그럴듯한 거짓 지명" 대신 "검증 가능한 물리 분수계"가 정직성 점수를 높인다.

### 비판 4. "세로 한글 제호·한자 낙관·'제첨·갈피·차례·읍지' 문법은 한국어권 밖의 Awwwards·FWA 심사위원에게 해석 장벽이거나 단순 오리엔탈리즘 장식으로 비칠 수 있다."
- **공격 지점**: 국제 심사위원단의 언어·문화적 거리감과 키치(kitsch) 경계.
- **대응**: ① 과잉 전통 장식(찢긴 종이, 붓글씨 본문, 낙관 애니메이션, 방안 눈금)을 이번 회차에서 전부 걷어내어, **현대적 스위스 그리드·산세리프 숫자(`Pretendard tnum`)와 목판 미학 사이의 팽팽한 긴장감**만 남긴다. ② 언어 없이도 3초 안에 이해되는 시각 인과(줌→색 침투, 범례 히스토그램 드래그→즉시 지도 격리, 수치 클릭→순위 막대)로 UX 완성도를 증명한다.

### 비판 5. "이중 타일 캐시(`ink`+`pig`) + JSON 11종 + 자체 호스팅 폰트 1 MB는 실제 모바일 LTE·저사양 기기에서 초기 로딩과 줌이 버벅여 성능 심사에서 감점된다."
- **공격 지점**: 데스크톱 헤드리스 벤치마크와 실기기 체감의 괴리.
- **대응**: 출시 게이트(Hard Budget)를 미리 고정한다.
  - 초기 핵심 로딩(표지 표시까지): `world/cities/states/nation/lenses/sources/ridges` + `Hahmlet`/`Pretendard`/`모필 4자` WOFF2 합계 **gzip ≤ 1.8 MB**, `font-display: swap` 적용, 층 5종(`wonders/resources/infrastructure/frontier/trade`)은 첫 화면 이후 지연 로딩.
  - 런타임 메모리: 모바일 `DPR ≤ 1.5`, 타일 LRU **≤ 28 MB** 강제, 저사양 기기 자동 단일판 폴백.
  - 출시 전 실제 iOS Safari + Android Chrome + Firefox 3종 기기에서 60fps 줌과 메모리 안정성을 실측 검증한다.
