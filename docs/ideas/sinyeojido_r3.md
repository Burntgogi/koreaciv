# 「신여지도 新輿地圖」 최종 디자인 명세 — 3회차 (v1 확정)

- 배포 경로: `site/yeojido/` (별도 프런트엔드, `../data/*.json` 및 `../data/ridges.json` 공유)
- 기존판 왕복: `site/` ↔ `site/yeojido/` 동일 URL 해시 유지 (`v`, `lens`, `city`, `state`, `item`, `route`, `report`, `ly`, `hide`, `turn`)
- 핵심 개념: **멀리서는 한지 위 먹선 목판 지도, 다가가면 칸마다 석채 빛깔이 배어 나오는 판, 렌즈를 켜면 통계가 종이 위에 한 판 더 찍힌다.**
- 전제: 새 통계·지도 원자료 추가 없음(보유 DEM·하천 재계산 `ridges.json`만 허용). 외부 CDN·프레임워크·런타임 빌드 없음. 감사 보고서(`docs/AUDIT_CODEX.md`)의 프런트엔드 결함(대비비·출처 누락·HTML 텍스트 노드·개별 JSON 실패 격리·해시 원자적 초기화·768px 줄바꿈·내부 영문 키 노출·단위 중복)을 설계 단계에서 원천 차단한다.

## 1. v1 범위 확정

### 1.1 핵심 (없으면 개념이 무너짐 — 5개)

1. **보유 DEM + WAMIS 하천 분수계 산줄기(`ridges.json`)와 가변 폭 먹필 리본**
   - `srtm30plus_korea.csv` + `world.json` 하천 396개로 빌드 시 계산. "산은 물을 건너지 않는다"(본류·지류 교차 `0건`) 빌드 검증 필수. 고유 산맥명 부여 금지. 직선·삼각형 톱니 폐기 → Catmull-Rom 가변 폭 리본 + 남동 사면 연먹 바림.
2. **이중 판목(먹판 + 채색판) 실시간 알파 블렌딩 (`k = smoothstep(5.5, 12.0, rc)`)**
   - 줌 멈춤 후 일괄 교체 금지. 휠·핀치 중 매 프레임 먹판 위에 채색판이 연속 침투한다. Mip 피라미드와 LRU 타일 캐시 상한은 구현자가 데스크톱·모바일 실측으로 최종 튜닝한다.
3. **전도 수묵 밀도와 렌즈 목판 덧찍기(`multiply`) + 색각 안전 33종 색띠**
   - 전도에서 한반도가 종이에 묻히지 않게 연안 3겹 쪽빛 바림 + 4단 수묵 음영으로 실루엣을 세운다. 렌즈는 `source-over` 덮어쓰기 대신 `multiply @ 0.82`로 한지 결·산줄기를 투과시키며, `extinction` 붉은 벽·`top_industry` 검정 벽을 제거하고 Oklch 단조 명도 + 범주 8색×목판 무늬를 적용한다.
4. **8방향 Imhof 현판 배치 + 위계별 경량화 + 광학 크기 이중 아이콘**
   - 16×16 검은 사각 마름모·근경 5산출 흰 벽돌 벽 폐기. 행정 위계 점수(수도 > 광역시 > 도청 > 100만 특례시 > 일반 시군)로 전도 수원 탈락·화성 잔존을 원천 차단하고, 15–18px용 단순 먹선(`ICONS_SM`)과 22px+ 세밀 먹선(`ICONS`)을 분리한다.
5. **한 장의 지도 종이 골격 + 기존판 1:1 기능 대응 및 URL 해시 양방향 전환**
   - 가운데 도판 + 둘레 여백(제첨·나라 장부·렌즈 갈피·층 단추·차례·축척)의 "기본 상태 침묵" 레이아웃. 기존판의 상단 수치 8종·순위 보고서 8종·렌즈 6묶음 33종·층 5묶음 18세부·도시/시도/전국/항목 패널·찾기·연감·도움말·공유를 모두 대응시키고 `site/` ↔ `site/yeojido/`를 해시 손실 없이 왕복한다.

### 1.2 완성도 (있어야 수상 수준 — 6개)

1. **모필 한자 제호(`新輿地圖` 4자 연묵 병치) + 고증 소전(또는 대체) 낙관**
   - 오픈 라이선스 모필 한자 글꼴에서 4자만 WOFF2 서브셋 추출해 한글 제호 옆에 연하게 곁들인다(추사체 호칭 금지, 연감에 실제 글꼴명·라이선스 명기). 낙관은 오픈 라이선스 소전 글꼴 4자 기계 추출을 1안으로 하되, 대조 불가 시 한글 낙관 또는 무늬 낙관으로 물러선다. *(2회차 후보 저장소 `masafont`·`bakudaifont`·`Yuji Syuku`·`kaiyuan-small-seal-font`·`LxgwSeal`의 라이선스·수록 글자·자형은 **미검증 상태**이며 구현자가 실물 파일로 직접 확인한다.)*
2. **모바일 전용 경험 (1줄 범례 리본 + 터치 칸 짚기 1줄 띠 + 3단계 바텀 시트 + 접히는 층 서랍)**
   - 모바일 표지 물리 그리드 분리(낙관–해안선 겹침 제거), 우상단 층 1단추 접기, 렌즈 44px 1줄 리본, 빈 땅 1회 탭 시 48px 칸 정보 띠(즉시 시트 덮임 방지).
3. **범례 분포 히스토그램 양방향 브러싱 + 렌즈 2문장 자동 요약**
   - 36막대 히스토그램 드래그·단계/범주 클릭으로 해당 구간 칸만 안료 유지(비선택 칸은 호분 마스크로 물러남). 키보드 구간 선택기 동시 제공.
4. **읍지 데이터 초상 2문장 + 보유 미활용 데이터 통합 + 팔도지(시도 장)**
   - `land_stats`(땅의 쓰임 띠), `jobs`(부가가치/종사자 전환 탭), `trade.json` HS2 상위 3품목, `farm`·`offices`(`<details>`), 살림 60px 전국 분포선, 16개 시도 장, 철도 파선·국립공원 23곳 영역·호수 16개 이름·교역로 히트테스트.
5. **원클릭 PNG 내보내기(1600×900 지도 + 1200×630 고을/렌즈 화보 카드) + 감사 출처 규약**
   - 클라이언트 오프스크린 캔버스 렌더링, `fonts.ready` 대기, `toBlob` + 모바일 Web Share/미리보기 시트 폴백. 실제 표시 레이어에 맞는 OSM ODbL·토지피복·경계·활성 렌즈 전체 출처(자르기 금지) 및 관측 범주 전수 범례 포함.
6. **접근성 기본선 및 실패 격리**
   - `<canvas>` 시멘틱 Fallback DOM(16시도→167고을 색인 + 활성 렌즈 상·하위 5곳 요약표 + `aria-live`), `prefers-reduced-motion` 전 경로 0ms 전환, JSON 개별 실패 격리 및 XSS 방지 텍스트 노드 렌더링.

### 2.5 아이콘 규칙

- **기본 도법**: `24 × 24` viewBox, `stroke-width: 1.6`, `stroke-linecap: round`, `stroke-linejoin: round`, 단일 먹선(DOM 인라인 SVG와 Canvas `Path2D` 공용). 이모지 전면 금지.
- **광학 크기 이중 세트**:

  1. 렌즈명 + 단위 + 닫기(`×` → 지형 복귀).
  2. 척도 시각화 + 양방향 브러싱: 연속형은 `multiply` 색띠 + 36막대 육지 분포 히스토그램(마우스 드래그 & 키보드 `←`/`→` 5구간 선택기), 구간·범주형은 항목 클릭/호버 격리(`최대 산업`은 관측 14개 범주를 2열 콤팩트 리스트로 표기). 브러싱 중 `"선택 구간 N칸 (P%) [풀기]"` 1줄 표시.
  3. 자료 없음 빗금 칩 + 칸 수 + 척도명(한글: `로그`/`선형`/`발산`/`구간`/`범주`).
  4. **2문장 자동 요약** (`aria-live="polite"` 겸용).
  5. 기준 시점·집계 기준(`basis`, 감사 #06 의사 수 정확 문구 반영)·출처·정의 접이식 `<details>`.
- **모바일 범례 (`≤ 700px`)**: 하단 갈피 위 **44px 1줄 리본**(렌즈명 + 색띠/상위 3칩 + `^` 펼치기 + `×` 닫기). 탭 시에만 드로어 확장.
- **한 화면 요소 상한**: 열린 `#flyout`과 `#legend`가 동시에 겹치지 않음(`#flyout` 열릴 때 범례는 유지하되 좌측 8px 이격). 범례 내 상시 노출 블록 **5개 이하**(정의·출처는 1줄 요약 또는 접이식).

## 4. 배율에 따른 변화표

`z = cam.scale / fitScale`, `rc = 25.0 * cam.scale` (CSS px 육각 칸 반지름, 1920×1080 전도 기준 `z = 1.0 → rc ≈ 3.4px`, 390×844 전도 기준 `rc ≈ 1.4px`). 전환 구간은 **`rc` 기준**으로 동작하므로 화면 크기가 달라도 시각 밀도가 일정하다.

## 5. 합격 기준 및 성능 예산

### 5.1 심사 관점별 검사 가능한 합격 기준 (5관점 × 5문장 = 25개)

#### 디자인 (Design)
1. **색 대비 전수 통과**: 모든 텍스트·배지·아이콘의 sRGB 상대휘도 대비가 본문 `≥ 4.5:1`, 큰 글자·UI 그래픽 `≥ 3.0:1`이며, `multiply @ 0.82` 적용 후 33종 렌즈 최짙은 색 위 `--ink` 대비가 `≥ 2.9:1`이다.
2. **전도 여백·실루엣**: 1920×1080 기본 전도에서 도판(`#plate` 내부) 면적이 전체 뷰포트의 `≥ 75%`를 차지하고, 대한민국 육지(`#FBF6E8`)와 주변국(`#DDD3BC`)·연안 쪽빛 바림의 명도 차가 시각적으로 즉시 분리된다.
3. **금 간 산줄기 제거**: `ridges.json` 빌드 검증에서 하천 본류·지류 교차 건수가 `0건`이고, 렌더링된 전도·중간·근접 화면에 직선 삼각형 톱니(`teeth`)가 존재하지 않으며 봉우리·고개 간 폭 변화가 육안으로 식별된다.
4. **제호·낙관 무결성**: 표지와 제첨에 오픈 라이선스 모필 한자 4자(`新輿地圖`)가 연묵(`α ≤ 0.25`)으로 곁들여지고, 임시 CSS 명조 빨간 사각형이 아닌 검증된 소전(또는 대체) SVG 낙관이 렌더되며, 문서·UI 어디에도 미검증 글꼴을 "추사체"라고 표기하지 않는다.
5. **시각 일관성**: `site/yeojido/` 전체 DOM과 캔버스에 시스템 이모지(`0건`), 흐린 `box-shadow`(`blur > 0` `0건`), 외부 CDN 요청(`0건`)이 존재하지 않는다.

#### 사용성 (Usability)
1. **전도 수원 공존 및 충돌 0건**: 1920×1080·1280×800 전도에서 서울·인천·수원·부산·대구·광주·대전·울산·세종 및 주요 도청 현판이 서로 겹치지 않고 공존하며, 전도에서 수원이 탈락하고 화성만 남는 현상이 발생하지 않는다.

1. **연속 먹→빛깔 침투**: 휠·핀치로 `rc`를 `4px → 14px`까지 확대하는 동안 줌을 멈추지 않아도 매 프레임 먹판 위로 석채 채색판이 연속적으로 배어 나오며(`k = smoothstep(5.5, 12.0, rc)`), 줌 종료 후 갑자기 색이 튀는 현상이 없다.

## 6. 가장 위험한 세 가지와 실패 시 물러설 자리

### 위험 1. 분수계 추출(`ridges.json`)의 시각적 어색함 또는 과도한 단절
- **실패 시나리오**: 0.9 km SRTM30+ 해상도에서 stream burning + "하천 교차 0건" 강제를 적용했더니 ① 호남·김해 평야에 지렁이 같은 잔능선이 남거나, ② 하천 교차 회피 절단 때문에 주능선이 뚝뚝 끊겨 연맥의 기세가 죽거나, ③ 제주 한라산 방사형 능선·북위 39° 절단선·리아스식 해안 곶이 부자연스럽게 튀는 경우.
- **물러설 자리 (2단계 폴백)**:
  1. **1차 완화(파라미터 재조정 + 하이브리드 스무딩)**: 평야 임계치를 강화(`Z_2km < 120m ∧ Rel_3km < 55m` 전면 제거)하고, 절단된 `tier 3` 주능선 간격이 `≤ 3 km`이면서 하천 본류와 교차하지 않는 미세 틈만 최단 고표고 안부 경로로 재연결한다. `tier 0`은 아예 끄고 `tier 3, 2, 1` 3단계만 쓴다.
  2. **2차 완전 폴백(분수계 선 축소 → 다중 스케일 수묵 기복 음영 주역 전환)**: 그래도 분수계 선이 부자연스러우면, `ridges.json`에서는 **5대강 대유역 경계(`A_sep ≥ 1,200 km²`이고 `Z_2km ≥ 250m`인 최상위 골격선 약 20–30개 체인)만 옅은 먹선(`α 0.48`)**으로 남기고, 나머지 산지 표현은 SRTM30+ 800m 래스터에서 사전 계산한 **고해상도 수묵 사광 음영·등고 바림 텍스처(정적 1장 PNG/WebP ≤ 200 KB)**로 주역을 넘긴다. "깨진 유리 금"과 "하천 교차"는 어떤 경우에도 돌아가지 않는다.

### 위험 2. 이중 판목(`ink` + `pig`) 실시간 블렌딩의 모바일 프레임 드랍 · iOS Safari 메모리 강제 리로드
- **실패 시나리오**: 모바일 Safari/저사양 Android에서 `inkTiles`와 `pigTiles`를 동시에 굽고 `globalAlpha`로 겹칠 때 GPU 텍스처 업로드·가비지 컬렉션이 몰려 줌 프레임이 15fps 이하로 떨어지거나, 캔버스 메모리 상한 초과로 탭이 강제 새로고침되는 경우.
- **물러설 자리 (3단계 성능 강등 사다리)**:
  1. **1차 조정**: Mip 간격을 $\sqrt{2}$에서 `2×`(`z = 1, 2, 4, 8`)로 성기게 줄이고, 모바일 `DPR` 상한을 `1.5 → 1.0`, 타일 LRU를 `14장 → 10장`으로 낮춘다.
  2. **2차 대체(전이 구간 해상도 절반)**: `0 < k < 1` 전이 구간 동안만 `pigTiles`를 절반 해상도(`256px` 논리 크기)로 구워 메모리·굽기 시간을 1/4로 줄이고, `k === 1` 도달 정지 시에만 정상 해상도 타일로 교체한다.
  3. **3차 완전 폴백(자동 감지 또는 모바일 단일 판)**: 연속 10프레임 `> 28ms` 또는 `deviceMemory ≤ 2` 또는 실측상 Safari 불안정 확인 시, 이중 판목 실시간 블렌딩을 끄고 **단일 판 캐시 + `rc = 8.5` 경계에서의 1회 220ms 캔버스 스냅샷 크로스페이드**로 자동 전환한다(데스크톱 실시간 블렌딩은 유지).

### 위험 3. 모필 한자 4자 · 소전 낙관 글꼴 실물 검증 실패 및 Pretendard OFL 수정본 처리 지연
- **실패 시나리오**: 2회차에서 조사한 오픈 라이선스 후보(`masafont`, `bakudaifont`, `Yuji Syuku`, `kaiyuan-small-seal-font`, `LxgwSeal`)를 실물로 내려받아 검증했더니 ① 라이선스 파일이 OFL 1.1과 상충하거나, ② `輿`·`圖` 글리프가 누락·일본 약자·이체자로 나와 한국어 제호와 어긋나거나, ③ 《설문해자》 소전 대조를 확신할 수 없는 경우.
- **물러설 자리 (무오류 대체 경로)**:
  1. **제호 곁글 한자 폴백**: 모필 후보가 모두 탈락하면 `LXGW WenKai TC` / `TW-Kai`(번체 정자 확인)로 1차 대체하고, 그마저 시각적 어울림이 부족하면 보유 중인 **`Noto Serif KR` 4자(`α 0.16`, 극도로 절제한 세로 명조 곁글)**로 물러선다. 어떤 경우에도 출처 불명 이미지 트레이싱이나 AI 생성 서예는 금지한다.
  2. **낙관 폴백 (확정 방침 준수)**: 소전 4자 고증·대조가 불가하면 한자 낙관을 과감히 접고, **한글 전각 낙관(「신여지도」 2×2 `Hahmlet 800` 음각 + 불규칙 인변 SVG 프레임)** 또는 **무늬 낙관(한반도 육각 격자 7칸 기하 인장 SVG)**으로 전환한다.
  3. **본문 글꼴 OFL 폴백**: `Pretendard` 서브셋의 예약 이름(`Reserved Font Name`) 변경 검증이 지연되면, `Pretendard` 공식 배포 동적 서브셋(자체 호스팅) 또는 예약 이름 없는 OFL 본문 글꼴(`IBM Plex Sans KR` 등 실물 라이선스 확인 후)로 교체한다.

## 7. 2회차 "심사위원 반론" 가운데 v1에서 해소되지 않는 것

v1은 아래 5가지 구조적 한계를 완전히 없애지 못한다. 숨기거나 말로 덮지 않고 배포 판단의 전제로 남긴다.
