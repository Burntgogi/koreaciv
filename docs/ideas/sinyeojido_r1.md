- 대상: `design2/` 시안 (별도 프런트엔드 본 제작 예정, `data/*.json` 공유)

## 1. 약점 9개에 대한 해법 탐색 (항목당 2–3안)

### 약점 1. 산줄기 — 칸 표고 계산의 '금 간 느낌'과 실제 지형 흐름 불일치

현재 `js/map/ridges.js`는 20.369 km²(중심 간격 약 4.8 km) 육각 칸의 `elev`만으로 역흐름과 최대 신장 나무(MST)를 뽑고, `terrain.js`의 `drawRidges`에서 직선 선분(`moveTo`/`lineTo`)과 등간격 삼각형 톱니(`teeth`)로 그린다. 4.8 km 격자에서는 고개와 하곡이 뭉개져 강과 능선이 엇갈리고, 직선+톱니 조합이 목판 연맥이 아니라 깨진 유리 금처럼 보인다.

#### 1-A. 보유 SRTM30+(0.9 km) + WAMIS 하천 제약 분수계(Watershed Divide) 사전 추출
- **무엇을 어떻게**: 이미 프로젝트가 보유한 `data/raw/terrain/srtm30plus_korea.csv`(30 arc-sec, 약 0.9 km)와 `world.json`의 `rivers`(WAMIS 396개 하천)를 기존 `pipeline/` 단계에서 결합한다. 하천 선을 따라 표고를 인위적으로 깎아(stream burning) 유역 분수계(drainage divide)를 추출하고, 다중 스케일 가우시안 스무딩(σ = 2 km, 6 km)으로 주능선·지맥의 차수(Strahler/유역 면적 위계)를 매겨 정적 폴리라인 JSON(`ridges.json`, ~100 KB)으로 굽는다. 이름은 붙이지 않으며 연감에 "SRTM30+ 표고·하천 분수계 계산선"으로 명시한다.
- **기대 효과**: 새 외부 자료 없이도 산경표의 본질인 산자분수령(山自分水嶺 — 산은 물을 건너지 않음)이 수학적으로 구현되어, 동고서저의 거시 골격과 하천 사이의 지리적 정합성이 극적으로 살아난다.
- **위험·반론**: 0.9 km 해상도에서도 평야부 저구릉 분수계는 모호할 수 있어, 표고·기복 임계치와 가지치기(pruning) 튜닝을 잘못하면 평야에 불필요한 잔가지가 생긴다.
- **난이도**: 중
- **선례**: 김정호 《대동여지도》(1861)의 산자분수령 기반 연맥 체계; 지형학의 D8/D∞ 흐름 누적 기반 분수계 추출(stream burning 기법).

#### 1-B. 직선 톱니 폐기 → 체인 병합 Catmull-Rom 곡선 + 가변 폭 먹필 리본과 편측 바림
- **무엇을 어떻게**: `ridges.js`의 분절된 세그먼트(`stride: 7`)를 분기점(차수 ≠ 2) 기준으로 긴 폴리라인 체인으로 병합한 뒤, `terrain.js`에서 Catmull-Rom 스플라인으로 보간한다. 직선과 기계적 삼각형(`teeth`) 대신, 각 정점의 `elev`와 차수에 따라 폭이 연속 변화하는 **가변 폭 리본 폴리곤**(봉우리 부근은 두껍고 고개에서는 좁아짐)을 채우고, 북서 사광(`terrain.js:115`의 `gx * -0.6 + gy * -0.8`과 동일) 반대쪽인 남동 사면에만 짧은 먹선 빗금(hachure)이나 옅은 먹 바림을 얹는다.
- **기대 효과**: "유리에 금이 갔다"는 가장 치명적인 시각 결함이 사라지고, 한 획으로 이어지는 동양화·목판화 특유의 유기적 산맥 붓질이 구현된다.
- **위험·반론**: 가변 폭 폴리곤을 타일마다 계산하면 초기 타일 굽기 시간이 늘어난다(단, 체인 경로와 폭 배열을 초기화 시 1회 계산해 두면 프레임 부담은 미미).
- **난이도**: 중
- **선례**: 《대동여지도》 목판의 굵기 변화가 살아 있는 연맥선; 전통 스위스 지형도의 사면 해칭(hachure).

#### 1-C. 줌 연동 산줄기 위계 해체(Scale-Dependent Ridge-to-Relief Morph)
- **무엇을 어떻게**: 전도(`z < 1.5`)에서는 최상위 1~2차 주능선만 또렷하게 남겨 한반도의 골격이 한눈에 읽히게 하고, 잔가지는 숨긴다. 도별도~군현도(`z 1.5→4.5`)에서 하위 지맥이 순차 등장하며, 칸 단계(`rc >= 10`)에서는 굵은 먹선 산줄기의 불투명도를 `0.9 → 0.32`로 낮추면서 `world.elev`·`world.relief` 기반의 칸 단위 구릉·암봉 먹선과 음영으로 주역을 넘긴다.
- **기대 효과**: 전도에서는 "과밀한 거미줄"이 사라져 시원해지고, 근경에서는 굵은 검은 선이 육각 칸·피복·도로를 짓누르는 간섭이 해소된다.
- **위험·반론**: 전도에서 잔가지를 너무 공격적으로 쳐내면 영남·호남 내륙 산지가 비어 보일 수 있어 지역별 최소 밀도 균형이 필요하다.
- **난이도**: 하

### 약점 2. "먹에서 빛깔로" 연속 전환 부재 (확대 종료 후 타일 일괄 교체)

현재 `terrain.js:228`은 `settled`(`now - lastZoom > 160 && !cam.anim`) 이후에만 새 축척 타일을 굽고, 타일 내부에 `k = smooth(5.5, 12, rc)`를 고정한다. 그래서 줌하는 동안은 옛 `k=0` 타일이 단순 확대만 되다가 멈춘 뒤 갑자기 색이 바뀐다.

#### 2-A. 이중 판목(먹판 + 채색판) 타일 캐시 실시간 알파 블렌딩
- **무엇을 어떻게**: `Terrain`의 타일 캐시를 **먹판(`k=0` 고정)**과 **채색판(`k=1` 고정)** 두 레이어로 분리한다(또는 전이 구간 `rc 5.0~13.0`에서 두 판을 쌍으로 유지). 매 프레임 `draw()`에서 먹판을 먼저 `blit`하고, 그 위에 채색판을 `ctx.globalAlpha = smooth(5.5, 12, rc)`로 실시간 겹쳐 그린다. 산줄기·물줄기·해안선·경계는 채색판/먹판에 동일 좌표로 찍거나 최상위 선판으로 분리해 블렌딩 중 선이 흐려지지 않게 한다.
- **기대 효과**: 휠·핀치 줌을 조작하는 *그 순간* 손끝에서 먹 지도 위로 석채가 실시간으로 번져 나와, 시안의 대표 문장("다가가면 칸마다 빛깔이 배어 나온다")이 60fps로 완성된다.
- **위험·반론**: 전이 구간에서 타일 메모리와 초기 렌더 비용이 약 1.8~2배 늘어난다. 모바일에서는 LRU 상한(예: 각 16장)으로 메모리를 제한해야 한다.
- **난이도**: 중
- **선례**: Leaflet / Mapbox의 다중 줌 레벨 타일 크로스페이드 기법.

#### 2-B. WebGL2 단일 프래그먼트 셰이더 바탕 합성 (모세관 한지 침투 전환)
- **무엇을 어떻게**: 25,857개 육각 칸의 바탕색(`cInk`, `cPig`, `wash`, `edge`, 렌즈값)을 정적 인스턴스 버퍼(또는 153×169 데이터 텍스처)로 WebGL2 캔버스에 올리고, 2D 캔버스는 산줄기·강·현판·아이콘 전용 투명 오버레이로 분리한다. 프래그먼트 셰이더에서 한지 섬유 높이맵(현재 `paper.js`의 512px 절차적 텍스처 활용)과 `k = smoothstep(5.5, 12.0, rc)`를 비교해 `smoothstep(paperHeight - 0.15, paperHeight + 0.15, k)`로 종이 섬유 골을 따라 석채가 먼저 스며드는 **물리적 수채 침투 효과**를 60fps로 계산한다.
- **기대 효과**: 160ms 타일 재래스터화 끊김 자체가 영구 소멸하고, Awwwards/FWA 심사에서 압도적인 시그니처 인터랙션이 된다. 렌즈 전환(`0.6초` 교차)도 셰이더 보간으로 0ms 비용에 처리된다.
- **위험·반론**: WebGL2 컨텍스트 소실(`webglcontextlost`) 대응과 기존 2D Canvas 폴백 경로가 필요하며, 2D 캔버스 1장 구조보다 디버깅 복잡도가 올라간다(외부 라이브러리 없이 순수 WebGL2 약 200줄 이내로 제한해야 원칙에 부합).
- **난이도**: 상
- **선례**: Stamen Watercolor 지도 타일의 수채 번짐 미학; FWA 수상 인터랙티브 지도 작품들의 WebGL 텍스처 마스킹 전환.

#### 2-C. 줌 중 스로틀링 점진적 타일 갱신 + 중심 우선 페이드인
- **무엇을 어떻게**: `settled` 대기를 없애고, 현재 `cam.scale`이 캐시 축척 `this.s`와 ±20% 이상 벌어지면(또는 90ms 스로틀 간격으로) 뷰포트 중심에서 가까운 타일부터 프레임당 1–2장(예산 8ms)씩 새 `k`로 굽고, 새 타일이 캐시에 들어올 때 220ms 동안 `globalAlpha`로 페이드인한다.
- **기대 효과**: 기존 `terrain.js` 구조를 거의 건드리지 않으면서 "줌 멈춤 → 뚝 바뀜"의 이질감을 크게 줄인다.
- **위험·반론**: 아주 빠르게 휠을 돌릴 때는 2-A·2-B만큼 완벽한 연속 침투가 나오지 않으며, 타일 경계에서 미세한 시간차가 보일 수 있다.
- **난이도**: 하

### 약점 3. 전국 화면이 심심함 (땅·종이 밝기 유사, 표지보다 약한 첫인상)

`d2_02_nation.png`에서는 `PAPER(#EFE6D2)`와 `LAND_INK(#F7F1E3)`의 명도 차가 작고, 해안 물띠(`alpha 0.07`)가 거의 보이지 않아 한반도 실루엣이 종이에 묻힌다. 표지(`d2_01_title.png`)의 강렬한 조형미가 본 화면에서 급격히 옅어진다.

#### 3-A. 다층 연안 쪽빛 수묵 바림(Coastal Wash) + 호분 뭍·연먹 주변국 명도 분리
- **무엇을 어떻게**: `terrain.js`에서 대한민국 육지 `LAND_INK`를 맑은 호분 톤(`#FBF6E8`)으로 미세 상향하고, 북한·일본(`FOREIGN`)은 명도를 낮춘 연먹 한지(`#DDD3BC`)로 가라앉힌다. `coast` 물띠를 현재 2겹(`alpha 0.07`)에서 **3겹 계단식 쪽빛 바림**(연안 1칸 `alpha 0.22`, 2~3칸 `0.11`, 4~5칸 `0.04`)으로 강화하고, `coastDist <= 2`의 조선 고지도식 잔물결 파문선을 전도(`rc >= 2.0`)부터 선명하게 살린다.
- **기대 효과**: 화려한 색을 쓰지 않고도 한반도 본토·제주·울릉·독도의 외곽선이 종이 위에서 부조처럼 또렷이 솟아올라 전도의 첫눈 흡인력이 크게 올라간다.
- **위험·반론**: 바다 쪽빛이 과해지면 "한지 위의 먹 지도"가 아니라 일반 파란 바다 지도로 돌아간다. 반드시 먼 바다(`wash` 감쇠)에서 종이색 `#EFE6D2`로 부드럽게 풀려야 한다.
- **난이도**: 하

#### 3-B. 전도 전용 초담채 수묵 산수 음영(Swisstopo-inspired Ink-Wash Hillshade)
- **무엇을 어떻게**: 현재 `cInk`는 `shade * 0.35`로 기복 음영이 거의 지워져 있다. `world.elev`(또는 SRTM30+ 사전 계산 0.9 km 음영맵)를 활용해 북서 사광 음영을 전도 먹판에 살리고, 해발 고도에 따라 평야(0~100m, 맑은 호분) → 구릉(100~400m, 엷은 미색) → 산지(400~900m, 옅은 송연먹) → 고봉(900m+, 은은한 청먹)의 **4단 수묵 담채**를 깐다.
- **기대 효과**: 표지의 거대 제목이 물러난 뒤에도, 태백·소백 산지와 호남·김해 평야의 대조가 한 폭의 수묵 산수화처럼 화면을 장악한다.
- **위험·반론**: 먹 음영이 너무 짙어지면 산줄기 먹선·시도 경계선·글자 대비가 떨어진다. 전체 명도 폭을 L* 82~96 사이의 좁은 고명도 구간에 가둬야 한다.
- **난이도**: 중
- **선례**: Eduard Imhof의 스위스 지형도(Swisstopo) 고명도 사광 음영 + 대기 원근 색조.

#### 3-C. 도곽(圖郭) 내 10리 방안 눈금 + 4방위 표기 + 전도 구도 밀도 조정
- **무엇을 어떻게**: `#plate` 이중 도곽선 안쪽 변을 따라 50 km(또는 경위도 1° 간격)의 미세한 **목판 방안 눈금(tick marks)**과 4방위 표기(東·西·南·北, 작은 `Hahmlet`/한자 11px)를 캔버스/CSS로 새긴다. `main.js`의 `focus` 계산에서 전도의 상하좌우 여유를 정돈하고, 동해·서해·남해 바다 이름의 자간·위치를 울릉도·제주도와 균형 잡히게 재배치한다.
- **기대 효과**: 전도 좌우의 넓은 여백이 "비어서 심심한 공간"이 아니라, 고지도의 장황(裝潢)과 격식을 갖춘 "의도된 여백"으로 전환된다.
- **위험·반론**: 눈금과 방위 표기가 너무 진하면 난외 UI(제첨·갈피·층)와 경쟁해 산만해질 수 있으므로 `--hair`(투명도 0.24 이하) 수준으로 극도로 절제해야 한다.
- **난이도**: 하
- **선례**: 《대동여지도》 목판 방격 및 도곽 표기.

### 약점 4. 렌즈가 종이 느낌을 덮음(소멸위험 붉은 벽) + 범주 16색 색각 이상·지각 균등 미검증

`d2_05_lens_extinction.png`는 `css(c, 0.93)` 불투명 채움과 어두운 적갈색(`#8E2A1B`)이 국토 대부분을 덮어 종이 질감과 산줄기를 삼켜 버린다. `d2_05c_lens_industry_zoom.png`의 `최대 산업`은 거의 검정(`#3A3530`)과 벽돌색(`#B4432B`)이 화면을 무겁게 짓누르며 적녹 색각 이상 검증이 빠져 있다.

#### 4-A. 목판 덧찍기(Overprint) 감산 합성(`multiply`) + 지형·산줄기 투과
- **무엇을 어떻게**: `terrain.js:385-391`의 렌즈 패스를 `source-over (alpha 0.93)` 대신, 호분 바탕(`LAND_INK`) + 미세 기복 음영 위에 **`ctx.globalCompositeOperation = 'multiply'`**(안료 명도를 종이 감산에 맞게 L* 48~94 범위로 밝게 보정, `alpha 0.78`)로 찍는다. 렌즈 위 산줄기(`drawRidges`)와 강(`drawRivers`)은 어두운 먹 대신 반투명 농먹/쪽빛으로 살아남게 하여 지형 맥락이 유지되게 한다.

#### 4-B. Oklch 지각 균등 색띠 재설계 + 편중 렌즈의 한지 중립화
- **무엇을 어떻게**: `js/map/lens.js`의 `rampAt`(sRGB 직선 보간)을 Oklch(또는 Oklab) 공간 보간으로 교체하고, 4개 안료 띠(`ju`, `jjok`, `nok`, `hwang`)와 발산 띠(`div`)를 명도(L)가 일정 간격으로 단조 변화하도록 재조정해 색각 이상(제1·2·3색각 이상) 시뮬레이션에서 **흑백으로 봐도 순서가 완벽히 구분**되게 검증한다. 특히 국토 70% 이상이 위험 구간에 몰리는 `extinction`(소멸위험지수)은 5단계 중 중간 '주의(0.5–1.0)'를 한지색에 가깝게 비우고, `0.2–0.5`는 연한 살구주홍, `0.2 미만`만 채도 있는 주홍(검붉은 벽 금지), `1.0 이상`은 맑은 쪽녹으로 배색해 예외 지역과 고위험의 층위를 동시에 살린다.

- **난이도**: 중
- **선례**: Björn Ottosson의 Oklab/Oklch 색공간; Cynthia Brewer의 ColorBrewer 2.0 색각이상 안전 색띠.

#### 4-C. 범주 16색 → 색각 안전 8색 + 목판 음각 무늬(Pattern Fill) 이중 부호화

### 약점 5. 도시 명패(현판)가 무겁고 반복적 + 충돌 처리로 수원 탈락·화성 잔존

`overlay.js:315`는 모든 도시 현판을 `x = sx - 10, y = sy - h - 13` 단일 방향에만 고정하고 단순 인구순으로 배치한다. 그래서 수도권에서 서울(928만) 바로 남쪽의 수원시(119만, 경기도청 소재지)가 서울 박스와 충돌해 탈락하고, 그 아래 화성시(100만, 일반시)가 살아남는다. 또한 모든 도청·광역시가 16×16 검은 사각형 마름모와 2.5px 검은 그림자를 달아 화면이 무겁고, 근경(`d2_03b_region_close.png`)에서는 산출 5개가 달린 거대한 흰 박스가 지도를 덮는다.

#### 5-A. 8방향 Imhof 후보 배치 + 행정 위계·공간 분포 가중 우선순위
- **무엇을 어떻게**: `overlay.js`의 `layoutBanners`에서 정렬 순서를 단순 `population` 내림차순에서 **위계 점수(`수도` > `광역시/도청소재지` > `인구 100만 특례시` > `인구 log 가중`)**로 바꾸고, 각 도시마다 8방향(북동·북서·남동·남서·동·서·북·남) + 필요 시 14~22px 짧은 직선/꺾임 지시선(leader line) 후보를 평가해 기존 배치 박스·해안선과의 겹침이 없는 최소 비용 위치를 선택한다.
- **기대 효과**: 서울·수원·인천·화성이 서로 밀어내지 않고 공존하며, 전도에서 도청소재지가 누락되는 지리적 어색함이 사라진다.
- **위험·반론**: 8방향 배치를 매 프레임 167개 도시에 돌리면 연산이 늘 수 있으나, 화면 내(viewport) 상위 40–60개 후보만 평가하고 직전 프레임 배치를 힌트로 쓰면 0.3ms 이내로 끝난다.
- **난이도**: 중
- **선례**: Eduard Imhof(1975, *Positioning Names on Maps*)의 점 지명 8방향 선호 순위 알고리즘; Apple Maps / Mapbox의 다중 앵커 라벨 배치.

#### 5-B. 위계별 현판 경량화 — 검은 사각 마름모 폐기 + 중소 고을 묵서 표기
- **무엇을 어떻게**: `drawBanners`의 16×16 검은 사각 마름모 블록을 완전히 제거한다(이미 자리 점 `◎/◉/○`가 지도표와 연동되어 위계를 말하고 있다). 대신 **1등급(수도·광역시·도청)**만 얇은 1px 테두리 + 좌측 3px 색띠(수도=주홍, 광역시·도청=먹)의 가벼운 현판(그림자 1.5px 연먹으로 축소)으로 두고, **2등급 이하 일반 시·군**은 박스 없이 반투명 한지 후광(`strokeText`, `LAND_INK`) 위의 정갈한 `Hahmlet` 묵서 + 작은 인구 수로만 표기한다. 또한 5대 산출(`withY`)은 `z >= 5.2`에서 모든 도시에 펼치지 않고 **선택·호버한 도시**에만 확장(또는 토글)해 `d2_03b_region_close.png`의 "흰 벽돌 벽"을 제거한다.
- **기대 효과**: 전도에서 검은 사각형이 도장처럼 흩뿌려진 무거움이 사라지고, 근경에서는 지형·피복·강·산줄기가 주역으로 되살아난다.
- **위험·반론**: 박스가 사라진 일반 시·군의 클릭 가능성(affordance)이 약해질 수 있다. 호버 시 밑줄/가벼운 한지 박스가 즉시 뜨고 커서가 낙관 네모(`is-hot`)로 바뀌면 충분히 보완된다.
- **난이도**: 하

#### 5-C. 줌 단계별 현판 정보 압축(LOD) + 전도 세로 명패 변주
- **무엇을 어떻게**: 전도(`z < 1.5`)에서는 현판의 인구 숫자(`928만`)를 떼어 지명(`서울`, `수원`, `부산`)만 좁고 단정하게 띄워(인구는 호버 풍선말·고을 장에서, 또는 `z >= 1.6`부터 표시) 가로 폭을 40% 줄인다. 좁아진 현판 덕분에 동서 폭이 좁은 한반도 본토에서 현판이 강과 산줄기를 가로막는 면적이 대폭 줄어든다.
- **기대 효과**: 전도가 훨씬 고요하고 옛 지도다운 여백미를 되찾으며, 충돌률 자체가 절반 이하로 감소한다.
- **위험·반론**: "차례"를 넘길 때 전도 현판의 인구가 바뀌는 시각 피드백이 줄어든다. 이를 보완하려면 차례 조작 시(또는 `is-past` 상태에서만) 전도 현판에 인구/증감 배지를 일시 노출하는 조건부 결합이 유리하다.
- **난이도**: 하

### 약점 6. 작은 지도 아이콘(15–18px)이 잘 안 읽힘

`overlay.js:219, 252-265`에서 15–18px 원·사각 배지 안에 실제 글리프가 `size * 0.66`(약 10–12px)으로 그려지며, `icons.js`의 24격자 다선 구조(`hydro` 댐+물결 2줄, `world_heritage` 지붕+기둥+문, `industrial` 톱니지붕 3칸)가 10px에서 뭉개진다.

#### 6-A. 광학 크기별 이중 아이콘 세트(Optical-Size LOD Glyphs)
- **무엇을 어떻게**: 활자의 광학 크기(Optical Size) 원리를 `js/icons.js`에 도입한다. `ICONS_SM`(< 20px용)을 별도로 만들어 모든 심볼을 **2~3획 이내의 면(fill) + 굵은 단선 실루엣**(예: 댐=단일 사다리꼴 둑+파도 1획, 산단=단일 굴뚝 실루엣, 공항=단순 십자 비행기 면, 세계유산=처마 1획+문 1칸)으로 단순화하고, `z >= 3.0` (`size >= 22px`)에서만 현재의 세밀한 24격자 목판 먹선(`ICONS`)으로 전환한다.
- **기대 효과**: 전도·도별도에서 15–18px 크기로도 각 기호가 즉시 판독되고, 확대하면 목판 세밀화로 전환되어 "다가갈수록 정교해지는 지도" 개념과 일관된다.
- **위험·반론**: 20여 개 아이콘을 두 벌로 유지보수해야 하지만, `icons.js`가 80줄에 불과해 관리 부담은 매우 작다.
- **난이도**: 중
- **선례**: Apple SF Symbols / Mapbox Maki의 11px·15px 광학 크기 분리 설계.

#### 6-B. 정수 픽셀 스냅 오프스크린 스프라이트 아틀라스 + 배지 내부 여백 축소
- **무엇을 어떻게**: `overlay.js:249`의 불가사의 배지 안쪽 흰 이중 사각선(`strokeRect`)을 제거해 내부 가용 공간을 확보하고, 글리프 비율을 `0.66 → 0.80`으로 키운다. 매 프레임 `ctx.scale(size / 24)`로 서브픽셀 벡터를 그리는 대신, 부팅 시(및 DPR 변화 시) 16·20·24px 정수 크기로 아이콘 배지를 **오프스크린 캔버스 아틀라스에 0.5px 스냅**해 캐싱한 뒤 `drawImage`로 찍는다.
- **기대 효과**: 같은 배지 크기에서 선명도와 가독성이 눈에 띄게 올라가고, 수백 개 아이콘이 떠 있는 근경의 매 프레임 렌더링 시간도 단축된다.
- **위험·반론**: 줌에 따른 연속적 크기 변화 대신 3단계 이산 크기로 바뀌므로 줌 중 미세한 크기 전환이 생길 수 있다(3단계 크기 점프 시 100ms 보간 또는 2단계 고정으로 완화).
- **난이도**: 하

#### 6-C. 밀집 구간 공간 군집화(Spatial Clustering) + 묶음 낙관
- **무엇을 어떻게**: `d2_03b_region_close.png`의 경주 일대(빨간 탑 5개 연달아 배치)나 울산·부산 연안처럼 동일 `group` 아이콘이 화면 거리 22px 이내에 2개 이상 몰릴 때, `overlay.js`의 `drawIcons`에서 단순 탈락(`continue`)시키지 않고 **대표 아이콘 + 우하단 작은 숫자 딱지(예: `5`)**로 묶어 20px 크기로 여유 있게 그린다. 클릭하면 해당 지점으로 부드럽게 확대되거나 묶음 목록 쪽지를 연다.
- **기대 효과**: 아이콘이 겹치며 작아지는 문제를 해결하고, 탈락으로 인해 "경주에 유산이 몇 곳 있는지" 숨겨지던 정보 손실도 복구된다.
- **위험·반론**: 군집화 로직이 매 프레임 실행되면 팬/줌 중 클러스터가 깜빡일 수 있으므로, 줌 단계(bucket) 단위로 안정적인 그리드 클러스터링을 써야 한다.
- **난이도**: 중

- **무엇을 어떻게**: `新輿地圖` 4자를 소전(小篆) 서법의 균정·곡선·방형 채움 구도로 직접 제작한 **인라인 SVG 벡터 경로**로 교체한다. 표지·로더·공유 카드용 **대인(大印, 92px)**은 고전 백문인(白文印, 붉은 바탕에 흰 전서)에 불규칙하게 깎인 수제 인변(테두리)과 미세한 인주 빈틈(돌결·종이결을 표현한 정적 벡터 마스크 또는 1회성 SVG `feTurbulence` 필터)을 얹고, 제첨·모바일 헤더용 **소인(小印, 26–32px)**은 획을 단순화한 고대비 미니 전서 SVG를 별도로 쓴다.
- **기대 효과**: `NotoSerifKR-VF.hanja.woff2`(19 KB) 의존을 줄이면서도, 임시 CSS 박스가 단번에 작품을 대표하는 진짜 전각 시그니처로 바뀐다.
- **위험·반론**: 전서 자형은 한자 고증 오류(오자·획 누락)가 생기면 안 되므로 《설문해자》 소전 자형(新·輿·地·圖)을 정확히 대조해 제작해야 한다.
- **난이도**: 중

#### 7-B. 제호 「신여지도」 옆 추사체 `新輿地圖` 연묵 병치 — 전용 서예 SVG vs 오픈 라이선스 서브셋
- **무엇을 어떻게**: 표지(`#intro`)의 거대 세로 제호 「신여지도」 바로 옆(우측 또는 좌측 수직 궤도)과 좌측 상단 제첨(`.slip`) 내부에 한자 `新輿地圖`를 세로로 연하게(`color: rgba(29, 26, 22, 0.22)` ~ `0.28`, 먹이 한지 뒷면에서 은은히 비치는 농도) 곁들인다. 구현 경로는 두 가지 중 선택한다:
  1. **전용 추사 서법 벡터 SVG(권장)**: 단 4글자(`新輿地圖`)이므로 추사 김정희 예서·행서 필획(굵은 가로획, 날카로운 파책, 조형적 불균형의 균형)을 살린 정교한 인라인 SVG(~3 KB)를 제작해 배치한다. 외부 글꼴 라이선스 분쟁·OS별 렌더링 차이를 0으로 만든다.
  2. **오픈 라이선스 추사체 계열 폰트 서브셋**: 예산군 공공저작물(공공누리 제1유형, 상업적 이용 및 변경 허용 여부 원문 재확인 필수) 「추사사랑체」 등 검증된 오픈 라이선스 추사 서체에서 `新輿地圖` 4자만 `fonttools`로 WOFF2(~4 KB) 추출해 자체 호스팅한다.
- **기대 효과**: 단정한 현대 명조(Hahmlet)의 한글 제호 옆에 자유롭고 기개 있는 추사체 한자가 반투명 먹으로 겹쳐, "옛 서화 제서 + 현대 데이터 지도"라는 정체성이 첫 1초 만에 각인된다.
- **위험·반론**: 제첨(`.slip`, 폭 48px) 안에서 한글과 한자를 나란히 넣으면 답답해질 수 있다. 제첨은 폭을 56px로 소폭 넓히거나 한글 제호 뒤에 추사체 한자를 **겹침 배면 워터마크(opacity 0.14)**로 까는 방식이 공간 절제에 유리하다.
- **난이도**: 중

#### 7-C. 상태 반응형 낙관 (인주 찍힘·호흡·과거 판 변주)
- **무엇을 어떻게**: 수제 전서 SVG 낙관에 상태별 미세 연출을 결합한다. 로딩 화면에서는 인주가 중앙에서 테두리로 천천히 차오르는 `clip-path` 호흡, 표지에서는 `stamp` 착지 순간 미세한 인주 번짐(0.15초), 과거 차례(`body.is-past`)에서는 제첨 낙관 옆에 작은 `舊` 또는 해당 연도 2자리(`20`~`25`) 세로 각인을 주홍으로 곁들여 현재 판과 과거 판을 직관적으로 구별한다.
- **기대 효과**: 낙관이 죽어 있는 장식이 아니라 사이트의 상태를 말없이 전하는 인터랙티브 표식이 된다.
- **위험·반론**: 애니메이션이 과하면 산만해진다. `prefers-reduced-motion`에서는 모든 연출을 정지하고, 평상시 지도 탐색 중에는 완전 정지 상태를 유지해야 한다.
- **난이도**: 하

### 약점 8. 모바일이 데스크톱을 접어 놓은 수준 (범례가 지도를 가림, 터치에서 칸 정보 없음)

`d2_02_nation_m.png`에서는 우상단에 원형 층 버튼 5개가 지도 위를 세로로 가리고, 렌즈를 켜면 `#legend`가 하단에서 크게 올라와 남해·제주를 덮는다. 터치에는 hover가 없어 칸의 표고·피복·렌즈값을 읽을 수 없고, `d2_01_title_m.png`에서는 표지 낙관이 강원도 해안선과 겹친다.

#### 8-A. 모바일 전용 1줄 컴팩트 범례 리본(Collapsible Legend Ribbon)
- **무엇을 어떻게**: `@media (max-width: 700px)`에서 렌즈 활성화 시 거대한 `#legend` 카드 대신, 하단 갈피(`#rail`) 바로 위에 **높이 44px짜리 1줄 범례 리본**(좌: 렌즈명, 중: 최소–최대 눈금이 붙은 색띠, 우: 펼치기 `^`·닫기 `×`)만 도킹한다. 사용자가 리본을 탭할 때만 반투명 한지 드로어가 올라와 분포 히스토그램·자료 없음 칸 수·출처·정의를 보여 준다.
- **기대 효과**: 렌즈를 켜고도 지도 가시 면적이 80% 이상 유지되며, 제주·호남이 범례에 가려지는 문제가 사라진다.
- **위험·반론**: 범주 렌즈(`최대 산업` 등)는 1줄 색띠에 다 안 들어간다. 범주 렌즈는 리본 안에서 가로 스크롤 칩(상위 범주 3–4개 먼저 노출 + `전체 보기`)으로 대응해야 한다.
- **난이도**: 하

#### 8-B. 터치 전용 "칸 짚기(Tap-to-Inspect + Long-Press Loupe)" & 하단 1줄 현황 띠
- **무엇을 어떻게**: 터치 입력(`e.pointerType === 'touch'`)에서 지도 빈 땅을 1회 탭하면 즉시 고을 장을 열어 지도를 덮지 않고, 해당 육각 칸에 먹선 조준 테두리를 고정하면서 하단(또는 상단 헤더 직하)에 **높이 48px 1줄 칸 정보 띠**(예: `강원 태백시 · 산 · 920m | 소멸위험 0.24 [고을 장 →]`)를 슬라이드 인한다. 같은 고을을 한 번 더 탭하거나 `[고을 장 →]`을 누를 때 고을 장을 연다. 추가로 350ms 길게 누른 채 손가락을 끌면 손가락 위 60px 오프셋에 실시간 칸 정보 말풍선이 따라오는 "손끝 훑기"를 제공한다.
- **기대 효과**: 모바일에서 데스크톱 hover의 완전한 등가물을 제공하며, 팬/확대 도중 실수로 고을 장이 자꾸 튀어나오는 피로도 함께 없앤다.
- **위험·반론**: 데스크톱의 "클릭 즉시 고을 열기"와 동작이 1단계 달라진다. 단, 도시 현판 자체를 직접 탭하면 바로 고을 장이 열리게 분기하면 의도가 명확히 분리된다.
- **난이도**: 중

#### 8-C. 3단계 제스처 바텀 시트(Peek / Half / Full) + 접히는 층 서랍 + 모바일 표지 재조판
- **무엇을 어떻게**: 모바일 `#city`를 고정 `62vh` 대신 터치 드래그 스냅이 되는 **3단계 바텀 시트**(요약 24vh — 이름·인구·5산출만 / 기본 56vh / 전체 92vh)로 개편하고, 지도 `insets.bottom`을 시트 높이에 맞춰 연동한다. 우상단 층 버튼 5개는 `층` 원형 버튼 1개(켜진 개수 점 표시)로 접어 탭할 때만 세로로 펼치고, 모바일 표지(`d2_01_title_m.png`)는 상단 38%를 전용 제목·부제·추사체 한자·낙관 영역, 중앙 48%를 지도 영역, 하단 14%를 CTA 영역으로 **물리적 그리드 분리**해 낙관이 강원도와 겹치는 결함을 없앤다.
- **기대 효과**: 모바일에서도 "데스크톱 축소판"이 아니라 손가락 동선에 맞춰 설계된 네이티브 지도 앱 수준의 공간감이 생긴다.
- **위험·반론**: 바텀 시트 내부 스크롤과 시트 드래그 제스처 충돌을 정교하게 처리해야 한다(`scrollTop === 0`일 때만 아래 드래그를 시트 축소로 전환).
- **난이도**: 중

### 약점 9. 캔버스 내용이 화면 낭독기에 보이지 않음

현재 `<canvas id="map">`에는 `aria-label` 한 줄만 있고, 지도 위 16개 시도·167개 고을·44개 렌즈 분포·칸별 통계가 보조 기술(스크린리더)에 전혀 노출되지 않는다.

#### 9-A. Canvas 시멘틱 Fallback DOM (시도→고을 계층 색인 + 렌즈 순위 표)
- **무엇을 어떻게**: `<canvas id="map">` 내부(및 인접 `.sr` 랜드마크)에 **16개 시도 → 167개 고을의 시멘틱 목차(`states.json`·`cities.json` 기반)**와 현재 선택된 렌즈의 **전국 상위 5곳·하위 5곳·구간별 칸 수 요약 `<table>`**을 동적으로 유지한다. 각 고을 링크를 선택하면 캔버스 카메라가 이동하고 고을 장(`#city`)으로 포커스가 넘어가며, 줌/이동 시 `aria-live="polite"` 영역이 "도별도, 화면 중심 경북 안동시 부근, 보이는 고을 12곳"처럼 간결한 위치 맥락을 알린다.
- **기대 효과**: 스크린리더 사용자가 지도 없이도 대한민국 167개 고을과 모든 렌즈의 전국 분포·극값을 완전하게 탐색할 수 있다.
- **위험·반론**: 167개 버튼을 항상 Tab 순서에 넣으면 키보드 전용 시각 사용자가 Tab을 너무 많이 눌러야 한다. 고을 색인은 건너뛰기 링크(`.skip`) 또는 접이식 `<details>` / 로빙 `tabindex`로 묶어 일반 키보드 동선을 해치지 않아야 한다.
- **난이도**: 하
- **선례**: W3C WAI-ARIA APG의 Canvas 대체 트리 패턴; Highcharts / Observable의 접근성 요약 테이블 패턴.

#### 9-B. 키보드 육각 칸 커서(Hex Focus Cursor) + 즉시 낭독 모드
- **무엇을 어떻게**: 캔버스에 포커스가 있을 때 `G` 키(또는 `Shift + 방향키`)로 "칸 짚기 모드"를 켜면 화면 중앙 육각 칸에 주홍 이중 테두리 포커스 링이 생기고, 방향키로 인접 육각 칸(`terrain.nb[cell * 6 + d]`)을 한 칸씩 이동한다. 이동할 때마다 `aria-live="assertive"`로 "전북 남원시, 산, 혼효림, 해발 610m, 소멸위험지수 0.21"을 낭독하고, `Enter`를 누르면 그 칸의 고을 장을 연다.
- **기대 효과**: 마우스를 쓰지 못하는 사용자도 "육각 칸 단위로 국토를 더듬어 읽는" 신여지도 고유의 공간 경험을 그대로 누릴 수 있다.
- **위험·반론**: 6방향 육각 격자에서 4방향 화살표 키 매핑이 약간 어긋날 수 있으므로, `grid.cx`/`grid.cy` 기준 목표 방향 벡터와 내적이 가장 큰 이웃 칸을 선택하는 방식이 직관적이다.
- **난이도**: 중

#### 9-C. 렌즈별 "데이터 2문장 자동 요약(Narrative Digest)" 범례·낭독 겸용 제공
- **무엇을 어떻게**: `renderLegend()` 시점에 이미 계산하는 `bins`, `none`, `total`과 `cities.json` / `lenses.json`의 실제 값만으로 2문장 사실 요약(예: *"소멸위험지수(2026-09). 육지 5,027칸 중 0.2 미만 고위험은 2,714칸(54.0%), 1.0 이상은 398칸(7.9%)이다. 시군 평균 최고는 화성시, 최저는 ○○군이다."*)을 생성해 범례 하단(및 `aria-live="polite"`)에 넣는다.
- **기대 효과**: 스크린리더 사용자에게는 지도를 보지 않고도 핵심 패턴을 5초 만에 전달하고, 비장애 사용자에게도 숫자를 읽는 첫 문맥을 열어 준다.
- **위험·반론**: 44개 렌즈 중 `land_values`(칸 단위)와 `by_county`(시군구 단위), `category`·`bins`·`diverging` 척도별로 문장 템플릿을 정밀하게 분기하지 않으면 어색하거나 부정확한 문장이 나올 수 있어, 척도별 4종 템플릿과 "자료 없음" 예외 처리가 필수다.
- **난이도**: 하

### 아이디어 1. [여는 장면·전환] "판목 각인 → 먹선 전개 → 바림" 다단계 오프닝 안무
- **무엇을 어떻게**: 현재 `main.js:256`의 표지 등장은 서울 중심의 단순 원형 그라디언트(`createRadialGradient`) 걷힘이다. 이를 1.8초 3막 안무로 재설계한다: ①(0–0.7s) 해안선과 1차 주능선·5대 강이 먹선으로 빠르게 그어지며 한반도 윤곽이 먼저 솟고, ②(0.5–1.3s) 서울에서 바깥으로 연안 쪽빛 바림과 먹 담채가 번지며, ③(1.0–1.8s) 세로 제호 「신여지도」·추사체 `新輿地圖`·전서 낙관이 차례로 맺힌다. 아무 키·클릭 시 즉시 완료되며 `prefers-reduced-motion`에서는 곧바로 최종 상태가 뜬다.
- **기대 효과**: 첫 2초에 "아, 이건 평범한 데이터 맵이 아니라 한 장의 목판화가 눈앞에서 찍히는 경험이다"라는 인상을 심어 FWA/Awwwards 첫인상 점수를 크게 끌어올린다.
- **위험·반론**: 재방문자나 빠른 탐색을 원하는 사용자에게 1.8초가 길게 느껴질 수 있다. `sessionStorage`로 같은 세션 재진입 시 스킵하고, 해시(`#lens=`, `#city=`) 직접 진입 시 즉시 생략하는 기존 규칙을 유지한다.

### 아이디어 12. [소소한 디테일 — 장인정신] 인쇄용 화보 포스터(`@media print`) + 단축키 목판 일람(`?`) + 외딴섬 빠른 닻

- **위험·반론**: 인쇄 시 캔버스 해상도가 화면 CSS 크기 그대로 찍히면 흐릴 수 있으므로 `beforeprint` 이벤트에서 캔버스를 일시 고해상도로 1회 렌더링하는 보강이 있으면 이상적이다.
- **난이도**: 하

### 아이디어 13. [성능·안정성] LRU 타일 캐시 상한 + 유휴 프리페치 + Web Worker 초기화 오프로드
- **무엇을 어떻게**: ① `terrain.js`의 `this.cache = new Map()`에 **LRU 상한(데스크톱 48장, 모바일 20장)**을 두고, 제거되는 타일 캔버스는 `cv.width = cv.height = 0`으로 명시적 해제해 모바일 Safari 메모리 한도 초과(탭 강제 리로드)를 원천 차단한다. ② 현재 부팅 시 메인 스레드에서 실행되는 `fillElev`, `coastDist`, `ownDist`, `cInk`/`cPig` 계산을 ES 모듈 Web Worker로 옮겨 로딩 바 애니메이션이 60fps로 끊기지 않게 한다. ③ 카메라가 정지하면 `requestIdleCallback`으로 뷰포트 외곽 1링 인접 타일을 미리 구워 패닝 시작 시 빈 틈이 안 보이게 한다.
- **기대 효과**: 데스크톱뿐만 아니라 구형 스마트폰·Firefox·Safari에서도 끊김·크래시 없는 수상작급 기술 완성도를 확보한다.
- **위험·반론**: ES 모듈 Worker는 로컬 `file://` 실행 시 제약이 있지만 HTTP 서버 환경(정적 호스팅 포함)에서는 정상 작동하며, 미지원 환경은 메인 스레드 폴백 5줄로 안전하게 처리한다.
- **난이도**: 중

## 4. "하지 말아야 할 것" 5개

수상작의 품격을 깎아먹거나 신여지도의 핵심 개념을 스스로 무너뜨리는 함정들이다.

1. **계산·장식을 사실처럼 이름 붙이거나 서사를 지어내지 말 것**
   - 표고·분수계 계산선에 "백두대간·낙동정맥" 같은 지명을 임의로 붙이거나, 데이터에 없는 역사·관광·감성 해설을 꾸며 넣지 않는다. 이 작품의 무게감은 230개 공공 출처와 "자료 없음"의 정직함에서 나온다.
2. **과잉 '전통 테마파크' 장식(Kitsch)을 얹지 말 것**
   - 찢어지거나 그을린 종이 테두리, 본문까지 붓글씨·궁서체 도배, 3D 두루마리 말림 애니메이션, 금박·단청 문양, 가짜 종이 얼룩 과다 투입을 피한다. 지금 시안이 뛰어난 이유는 **현대적 그리드·타이포(Hahmlet + Pretendard)와 고지도의 절제된 문법이 만드는 긴장감** 때문이다.
3. **상용 4X 전략 게임의 UI·시각 어법을 흉내 내지 말 것**
   - 어두운 네온/글래스모피즘 패널, 금화·망치·플라스크식 게임 HUD 배지, 거대한 원형 "다음 턴" 버튼, 화려한 입자·반짝임 이펙트를 들이지 않는다. 전략 판의 문법은 이미 "육각 칸·산출·차례·불가사의"라는 구조에만 녹여 두고, 겉모습은 끝까지 한 장의 지도 종이로 유지한다.
4. **전도(全圖)에 모든 레이어·정보를 한꺼번에 욱여넣지 말 것 (LOD 파괴 금지)**
   - 전도부터 철도·도로·수백 개 자원 아이콘·5대 산출 현판·미니맵을 동시에 열어 두면 "멀리서는 고요한 먹 지도, 다가가면 살아나는 판"의 극적 대비가 죽는다. 정보는 반드시 줌과 사용자 의도에 따라 서서히 열려야 한다.
5. **거대 외부 라이브러리·CDN·빌드 의존을 들여오지 말 것**
   - Mapbox GL, Three.js, D3 전체 번들, 외부 웹폰트 CDN, html2canvas 같은 외부 패키지를 끌어오면 0.4–0.7ms 프레임 렌더링의 경쾌함과 자체 호스팅·무빌드 아키텍처의 순수함이 깨진다. 모든 시각 기법은 순수 ES 모듈 + Canvas 2D(또는 200줄 이내 무의존성 WebGL2) + 자체 호스팅 자산으로 완결한다.
