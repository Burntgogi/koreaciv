# 시안 2 — 「신여지도 新輿地圖」

두 번째 디자인 시안이다. 제품 재작성이 아니라, 디자인을 판단할 수 있을 만큼만 움직이는 시제품이다.
위치 `design2/` · 자료는 `design2/data/*.json` (2026-11-27 에 `site/data` 를 복사한 스냅숏, version `phase5c-20261001`) 만 읽는다. `site/`, `pipeline/`, `data/` 는 건드리지 않았다.

실행: `cd design2 && python -m http.server 8732` → `http://localhost:8732/`
갈무리: `python design2/tools/shot.py` (19장, `docs/screenshots/d2_*.png`) · 점검: `python design2/tools/check.py`

## 1. 개념

**먹에서 빛깔로.** 멀리서 보면 한지에 먹으로 찍은 목판 지도다. 산은 낱낱의 봉우리가 아니라 이어지는 산줄기로, 물은 쪽빛 한 줄로, 고을은 현판으로 놓인다. 다가가면(칸 반지름 5.5→12 px) 칸마다 안료 빛깔과 피복 무늬가 배어 나와 판 놀이의 육각 판이 되고, 렌즈를 켜면 통계가 종이 위에 한 판 더 찍힌다. "안 가 본 땅은 먹선, 들여다본 땅은 빛깔"이라는 전략 놀이의 문법을 옛 지도의 문법(먹선 → 채색)에 겹친 것이 이 시안의 한 가지 생각이고, 화면의 나머지는 모두 여기에 맞췄다.

화면 전체는 **지도 한 장**이다. 가운데가 도판(지도), 둘레 여백에 제첨(題簽, 세로 제목 띠)·나라 장부·렌즈 갈피·층 단추·차례·축척이 지도의 난외 주기처럼 앉는다. 유리 카드도, 어두운 대시보드도, 이모지도 없다.

이름 「신여지도」는 '새로 만든 땅 그림'이라는 보통 말이다. 특정 게임의 이름·자산·UI 틀·글꼴·아이콘은 쓰지도 본뜨지도 않았다.

## 2. 디자인 체계

**글자** (한글 먼저, 모두 `design2/fonts/` 에 자체 호스팅)

| 쓰임 | 글꼴 | 까닭 |
|---|---|---|

| 본문·단추·표 | Pretendard (가변) | 작은 크기에서 고른 회색도, 고정폭 숫자(tnum) |

렌즈 색띠는 자료의 색 대신 안료 띠 네 가지(주·쪽·녹·황, 종이색에서 시작)와 갈림 띠(쪽↔주), 범주 16색을 쓴다(`js/map/lens.js`). 척도 규칙과 정의역은 자료 그대로다.

**격자** 8 px. 여백(도판 바깥) 위 80 · 아래 64 · 좌우 88 px(390 px 에서는 60 · 68 · 6). 도판 둘레는 겹줄 도곽선. 그림자는 흐린 그림자 대신 판목처럼 어긋난 먹 그림자(4 px, 0 blur) 하나만 쓴다.

**움직임** — 뜻이 있을 때만.
- 불러오기: 낙관이 숨 쉬고 가는 선이 찬다("땅과 물을 새기는 중…").
- 표지: 서울에서 바깥으로 종이가 걷히며 지도가 번져 나오고(캔버스), 제목 네 글자가 흐림에서 맺히고, 낙관이 찍힌다.
- 표지 → 지도: 도곽선이 여백 자리로 줄어들고 카메라가 가운데로 옮겨 가며, 제첨 → 장부 → 갈피(하나씩) → 층 → 차례 순으로 들어온다.
- 렌즈: 이전 판 위에 새 판이 0.6초에 걸쳐 찍힌다(조각 교차). 고을: 카메라가 날아가고, 영토에 주홍 테가 그어지고, 장이 오른쪽에서 넘어오며 이름 → 숫자 → 단 순으로 맺힌다.
- `prefers-reduced-motion` 이면 전환·날기·관성·번짐을 모두 끈다(헤드리스에서 켜고 확인: 표지에서 곧바로 지도 자리로 간다).

**아이콘** 24 격자, 굵기 1.6 의 둥근 먹선 한 벌 35개(`js/icons.js`). 같은 경로를 DOM(SVG)과 캔버스(Path2D)에서 쓴다. 산출은 벼 이삭(식량)·메(생산)·엽전(금)·첨성대(과학)·붓(문화)·갓 쓴 사람(인구). 지도 위에서는 묶음을 꼴로 가른다: 불가사의 = 주홍 네모(낙관), 기반시설 = 쪽빛 동그라미, 교역 = 녹색 마름모, 자원 = 종이색 동그라미.

**커서** 지도 위 고리 / 끌 때 먹점 / 고을·아이콘 위 낙관 네모.

## 5. 진짜인 것과 흉내인 것

**진짜 (자료에서 그대로)**: 칸 지형·피복·호수·강·길, 고을 167곳의 자리·인구·산출·순위·산업·피라미드·교역·살림, 렌즈 44개의 칸 값과 정의, 층 아이콘(불가사의·자원·기반시설 항목), 화물 흐름, 접경 17곳, 연감의 출처 230건과 일러두기, 범례의 분포 막대와 "자료 없음" 칸 수.

**그림을 위한 계산 (자료 값은 아님)**: 산줄기는 칸 표고에서 능선과 고개를 뽑아 이은 것(`js/map/ridges.js`)으로, 산경표의 대간·정맥 줄기와 꼭 같지 않다. 바다 담채가 멀어질수록 종이로 돌아가는 것, 외딴 섬 칸을 땅 비율만큼의 작은 섬으로 그리는 것도 그림 처리다. 바다 이름 셋(동해·서해·남해)은 손으로 놓았다.

**시안용 가정**: 렌즈 여섯 묶음은 지금 자료의 열 묶음을 접은 것(사람 ← 사람·나이·지속, 일상 ← 일상·배움·신앙 …). 층 다섯 묶음도 지금 종류를 내가 나눈 것이다(자원 ← 발전·댐·산단·광산·특산·주력 업종·어항, 기반시설 ← 길·역·공항·무역항, 교역 ← 화물 흐름·수출 거점). 줄어든 새 자료가 오면 표(`LENS_GROUPS`, `KIND_RULE`)만 바꾸면 된다.

**없거나 얕은 것**
- 고을 장에 없는 항목: 업종별 종사자, 농가, 청사, 토지피복 통계, 품목(HS)별 수출입, 자치구별 범위의 자세한 값. 시도 화면, 국립공원·교역로·아이콘의 자세한 장도 없다(아이콘은 풍선말 + 그 고을 장으로 간다).
- 차례는 인구만 바꾼다. 렌즈·산출은 최신 시점뿐이다.
- 공유 카드는 DOM 으로 짠 화면이다. 그림 파일로 내보내기, og:image 만들기는 없다(「공유」는 카드 화면을 새 창으로 연다).
- 철도 선, 국립공원 영역, 미니맵 없음. 찾기는 고을만.
- 손가락 화면에서는 풍선말이 없다.

**확인한 범위**: 헤드리스 Chromium 한 가지에서만 봤다(1920×1080, 390×844). Firefox·WebKit·실제 휴대전화는 보지 않았다. 움직임은 끝 상태 갈무리와 상태 전환(`tools/check.py`)으로만 확인했고 영상으로 보지는 않았다. 이동 성능은 헤드리스에서 한 프레임 그리기 0.4–0.7 ms(조각 복사 + 덧그림), 프레임 간격 중앙값 16.7 ms 였다. 실제 기기의 60 fps 는 재지 않았다.

## 6. 내놓는 두 길 — 기술 평가

**차이가 어디에 있나.** `design2/` 는 약 3,450줄이다. 기존 `site/` 와 견주면:

| 갈래 | 내용 | 몫(어림) |
|---|---|---|
| 그대로 같이 쓸 수 있는 것 | `data/*.json`, 칸 수학(`hex.js`), 카메라의 뼈대, 렌즈 척도 규칙, 숫자 적기, 조각(tile) 캐시 방식, 현판 겹침 피하기 | 15% |
| 껍질 (토큰만 바꾸면 되는 것) | 색·글꼴·간격, 렌즈 색띠, 지형 색 상수, 현판 색 | 15% |
| 구조 | 화면 짜임(도판 + 여백 ↔ 꽉 찬 지도 + 뜬 패널), 길찾기(세로 갈피 + 목록 ↔ 아래 렌즈 띠), 고을 화면의 꼴과 순서, 표지·전환 안무, 범례(분포 막대), 차례, 지도표, 아이콘 한 벌(SVG ↔ 이모지), 좁은 화면 짜임 | 40% |
| 그리기 패스 | 산줄기 추출과 톱니, 해안 물띠·물결, 바다 담채 감쇠, 외딴 섬, 조각 안의 길, 확대에 따른 먹↔빛깔 섞기, 렌즈 교차, 번짐 | 30% |

껍질은 15% 남짓이고 나머지는 구조와 그리기다. 색 토큰을 바꿔 끼우는 것으로는 이 시안이 되지 않는다.

**(a) 기존 사이트 안의 테마 전환** — 한 번 눌러 바꾸려면 `main.js`, `terrain.js`, `banners.js`, `panel.js`(757줄), `lensbar.js`, `almanac.js` … 모듈마다 두 갈래가 생긴다. DOM 뼈대가 달라 CSS 만으로는 못 바꾸고, 그리기 패스가 달라 렌더러도 둘을 실어야 한다. 지금 `site/` 를 다른 작업자가 다시 짓고 있어 같은 파일에서 부딪힌다. 어림 12–15일, 잘 돌아가는 기존 화면이 깨질 위험이 크고, 끝나도 두 디자인이 서로의 구조에 묶인다.

**(b) 같은 자료를 읽는 별도 프런트엔드** — `design2/` 를 그대로 키운다. 겹치는 것은 자료와 작은 핵심 모듈뿐이다.
- 핵심 모듈 공유(`hex.js`, 카메라, 렌즈 척도, 숫자 적기)를 한 곳에서 불러오게 정리: 1일
- 줄어든 자료(렌즈 32 · 묶음 6 · 층 5)에 맞추기: 1일 (표 두 개와 `setLayers`)
- 빠진 화면 채우기(고을 장 나머지 항목, 시도 장, 아이콘·공원·교역로 장, 철도 선·공원 영역): 4–5일

## 7. 지금 가장 약한 곳

1. **산줄기의 정확성.** 표고 칸에서 뽑은 줄기라 군데군데 금 간 것처럼 보이고, 백두대간·정맥의 알려진 흐름과 어긋나는 곳이 있다. 이 시안의 얼굴인 만큼, 출시하려면 산경표 줄기를 자료로 받아 그 선을 굵게 쓰고 계산 줄기는 잔가지로만 써야 한다.
2. **먹 → 빛깔 전환이 이어지지 않는다.** 빛깔은 확대가 멈춘 뒤 조각을 다시 그릴 때 바뀐다. 확대하는 동안에는 옛 조각이 늘어났다가 바뀐다. 개념이 약속하는 "배어 나옴"에 못 미친다(두 판을 겹쳐 섞어야 한다).
3. **전도가 조용하다.** 숨은 쉬지만 첫눈에 붙잡는 힘은 표지보다 약하다. 땅과 종이의 밝기 차가 작다.
4. **렌즈를 켜면 종이 느낌이 묻힌다.** 소멸위험지수는 붉은 벽이 된다. 범주 16색은 색각 이상 검증을 하지 않았고, 색띠도 지각 균등 보정을 하지 않았다.
5. **현판.** 검은 마름모가 되풀이되어 무겁고, 겹침 규칙 때문에 전도에서 수원이 빠지고 화성이 남는 식의 일이 생긴다.
6. **작은 아이콘.** 지도 위 15–18 px 에서 댐·수력 같은 꼴은 잘 읽히지 않는다.
7. **낙관.** 전서체가 아니라 명조 한자를 붉은 네모에 넣은 것이라, 새긴 도장의 맛은 없다.
8. **좁은 화면.** 쓸 수는 있지만 넓은 화면을 접은 것이다. 범례가 지도를 가리고, 손가락으로는 칸 값을 볼 수 없다.
9. **캔버스 안의 내용은 화면 낭독기에 닿지 않는다.** 찾기와 고을 장만 닿는다.
